## 1. 问题陈述

删除阶段直接 `file_path.unlink()`，全仓库无回收站、无删除审计清单。唯一的批量护栏有两处放行口：

1. `force=True` 时整批放行；
2. `CLEANUP_GUARD_MIN_SAMPLE = 20` 使评分图少于 20 张的目录完全不启用护栏。

后果：一个 15 图的目录，配置错误（`--threshold 100` 导致全部不达标）即可一次 `--apply` 全量抹除且无任何拦截；`--apply --force` 组合下护栏等价于不存在，用户图片既无回滚路径、也无事后可追溯的删除记录。

现状代码片段（`flashgaze/core/cleanup.py`）：

```python
        if dry_run:
            pending_list.append(asdict(s))
        else:
            try:
                file_path.unlink()
                deleted_list.append(asdict(s))
                deleted_count += 1
            except OSError as e:
```

## 2. 修复目标

| 编号 | 目标 | 判定口径 |
| --- | --- | --- |
| G1 | 实际删除默认先进 workspace 内回收站，字节完整保留 | 删除后 `<ws>/.flashgaze_deleted/<批>/<原相对路径>` 存在且 SHA256 与原文件一致 |
| G2 | 每次实际删除落盘审计清单，可追溯 | `<ws>/.flashgaze_deleted_<UTC>_<pid>.jsonl` 每条含 original_path / trash_path / sha256 / size / score / mode |
| G3 | `force` 必须绑定已核对的 dry_run 清单指纹 | `force=True` 且指纹缺失或不匹配 → 整批拦截、一张不删、`confirm_required=True` |
| G4 | 小目录同样受护栏保护，阈值可配置 | `CLEANUP_GUARD_MIN_SAMPLE` 20→6，并开放 CLI 旗标 + 配置文件键 |
| G5 | 一键回滚闭环 | `flashgaze restore <清单>` 按审计记录把文件搬回原路径 |

## 3. 依赖声明

- **新增/变更依赖：无**。仅使用标准库 `hashlib / json / os / shutil / stat / time / pathlib / datetime`。
- **不引入 `send2trash`**：系统回收站删除后路径不可预测、跨卷与网络盘行为不一致，审计清单无法给出可恢复路径，且测试必须打桩。改用 workspace 内同卷 rename 回收站：零新增依赖、原子、路径可记录、可真机测试。
- 运行/检查命令全部为仓库既有（`Makefile`：`python -m ruff check .`、`python -m ruff format --check .`、`python -m mypy`）。

## 5. 错误处理

| 场景 | 分支行为 | 日志 | 调用方可观测 |
| --- | --- | --- | --- |
| 回收站 `Path.replace` 抛 `OSError`（跨卷/权限/被占用） | **绝不降级为 unlink**（那会制造"以为进了回收站其实直接删了"的假安全）；该张进入 `blocked`，原文件保留 | WARNING | `blocked[].kind == "delete_failure"`，reason 前缀「删除失败」（沿用既有 `entry.py` kind 判定 → `EXPORT_ERROR`） |
| `--no-recycle` 模式 `unlink` 抛 `OSError` | 同上，原文件保留 | WARNING | `kind == "delete_failure"` |
| SHA256 读取失败 | 记 `"sha256": null`，**继续删除**，不阻断 | WARNING（每进程一次） | 审计记录 `sha256: null` |
| 审计清单落盘失败（只读目录/磁盘满） | 继续删除，不回滚已删项 | WARNING（每进程一次，含清单路径） | `summary["audit_failed"] = True` |
| `force=True` 无指纹 / 指纹不匹配 | **整批拦截，一张不删** | WARNING | `summary["confirm_required"]=True`，`blocked[].kind == "confirm_required"`；CLI → `PARAM_ERROR(1)`；MCP → `status="blocked"` + `code=1` |
| 回收站目标文件已存在（同名冲突） | 追加 `.1` / `.2`… 后缀，不覆盖既有回收副本 | DEBUG | 审计记录 `trash_path` 为实际落点 |
| `restore` 清单不存在 / 非法 JSON 行 | 跳过该行并计数，不抛异常 | ERROR | CLI → `PARAM_ERROR`；返回 `restored/failed/skipped` |
| `restore` 目标路径逃逸 workspace | 跳过该行（与检查点 B 同款防护） | WARNING | `blocked[].kind == "outside_workspace"` |
| `restore` 回收站文件已丢失 | 跳过并计数 | WARNING | 计入 `failed` → CLI `EXPORT_ERROR` |

纪律：所有 best-effort 增强（SHA256、清单落盘）失败均**不阻断**原本可成功的删除或恢复——安全增强不得变成可用性回退（与 `exif_writer._undo_warning` 同款）。

## 6. 参数校验

### 6.1 新增函数签名（`flashgaze/core/cleanup.py`）

```python
def pending_fingerprint(paths: Iterable[str | Path]) -> str:
    """待删清单指纹：已解析绝对路径去重排序后 '\n' 拼接，SHA256 前 12 位。"""


def classify_and_delete(
    workspace: str | Path,
    scored: list[ImageScore],
    dry_run: bool = True,
    force: bool = False,
    *,
    confirm_fingerprint: str | None = None,  # force=True 时必填且须等于本次 fingerprint
    guard_min_sample: int = CLEANUP_GUARD_MIN_SAMPLE,
    recycle: bool = True,  # False(=--no-recycle) 直接 unlink，仍写审计
    audit_manifest: Path | None = None,  # None → <ws>/.flashgaze_deleted_<UTC>_<pid>.jsonl
) -> dict[str, Any]: ...


def restore_from_manifest(manifest: str | Path, dry_run: bool = False) -> dict[str, Any]: ...
```

### 6.2 校验规则

| 参数 | 类型 | 必填 | 边界与非法值处理 |
| --- | --- | --- | --- |
| `confirm_fingerprint` | `str \| None` | `force=True` 时必填 | 空串 / 空白串视为缺失；大小写不敏感（统一 `strip().lower()` 后比较）；不匹配 → 拦截 |
| `guard_min_sample` | `int` | 否（默认 `CLEANUP_GUARD_MIN_SAMPLE`） | `<1` → WARNING 并钳到 1；非法类型/溢出 → WARNING 回退默认 6；**不提供 0=关闭通道**（放行请用 `--force` + 指纹） |
| `recycle` | `bool` | 否（默认 True） | 走 `_coerce_bool` 既有强转（配置文件 `"false"` 不得被当成真） |
| `audit_manifest` | `Path \| None` | 否 | 测试注入用；生产恒为 None |
| CLI `--confirm-fingerprint` | `str` | `--force` 时必填 | 缺失 → `PARAM_ERROR` 且**在评分之前**拒绝（不消耗算力） |
| CLI `--no-recycle` | flag | 否 | 无回收点属危险操作，须与 `--force` 同时给出；否则 `PARAM_ERROR`（与 H-2 `--no-exif-backup` 同语义） |
| CLI `--guard-min-sample N` | `int` | 否 | `default=None`（不覆盖下层配置，契约测试硬约束）；值域由 `_clamp_cleanup_guard_min_sample` 统一处理 |
| MCP `confirm_fingerprint` / `recycle` | `str \| None` / `bool` | 同 CLI | MCP 未传指纹而 `force=True` → `status="blocked"` + `code=1` |
| `restore <manifest>` | 路径位置参数 | 是 | 不存在/不可读 → `PARAM_ERROR`；相对路径按 CWD 解析；**不做**越界输出校验（目标路径来自清单内的 `original_path`，逐条做 `relative_to(workspace)` 校验） |

### 6.3 返回结构增量（向后兼容，只加键）

- `summary` 新增：`fingerprint`（str）、`confirm_required`（bool）、`delete_manifest`（str \| None）、`recycle`（bool）、`audit_failed`（bool）。
- 顶层新增：`delete_audit`（list[dict]，与 `deleted` 一一对应的审计记录）。
- `deleted` 仍为 `asdict(ImageScore)` 列表，**不污染 `ImageScore` 契约**。
- blocked `kind` 枚举新增 `confirm_required`，其余五种（`guard` / `outside_workspace` / `not_regular_file` / `stat_failed` / `delete_failure`）不变。

## 10. 关键设计决策

1. **回收站目录命名为隐藏目录 `.flashgaze_deleted/`**：`utils/image_io.py::iter_images` 已整体跳过以 `.` 开头的目录与文件，回收站副本与 `.flashgaze_deleted_<ts>.jsonl` 天然不被 score/export/cleanup 二次扫描，**故不修改 `exclusion_dirs()`**（其返回集合被两个既有用例断言精确相等）。
2. **指纹只取待删路径集合**：`sha256("\n".join(sorted(resolved_paths)))[:12]`。VLM 抖动改分数但不改路径集合；只有路径增减才应视为"清单变了"。
3. **移动失败绝不降级 unlink**：见 §5。
4. **SHA256 / 清单落盘均为 best-effort**：见 §5。
5. **`--no-recycle` 纳入但受 `--force` 约束**：与 H-2 `--no-exif-backup` 同语义；仍强制写审计清单。
6. **退出码复用既有语义，不新增码**：`confirm_required` → `PARAM_ERROR(1)`；回收站失败 → `EXPORT_ERROR(5)`。
7. **性能**：SHA256 每图顺序读一遍（1MB chunk），仅在实际删除时发生；删除循环保持单线程，避免回收站目录竞争。
