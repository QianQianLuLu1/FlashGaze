## 3. 错误处理总原则（全部子任务共用）

- 与仓库既有风格一致：逐项 `except OSError` 降级/记录、不中断批处理；日志中文 + lazy `%` 格式化；模块级 `logger = get_logger()`。
- 权限类操作（chmod/chown/unlink）一律 best-effort + 注释说明权衡：失败不阻断主写入流程，但必须可观测（DEBUG/WARNING 日志或 last_failures）。
- 清理类操作（tmp/bak 删除）失败不得掩盖原始异常、不得把「写入成功」误判为「写入失败」。
- 不新增对外 CLI 参数；不修改 `export_images` / `atomic_write_*` 对外签名（仅 entry.py 改传解析后的绝对路径；webui/mcp 调用方零影响）。

## 4. 参数校验总则

- `--export-dir`：沿用 `_safe_output_path(config.export_dir, config.directory)` 的 workspace 包含性硬拒绝（越界 `sys.exit(2)` → main 收敛为 ExitCode.PARAM_ERROR=1）；N-1 使「校验通过的路径」与「落盘路径」同源，杜绝「校验基于 workspace、落盘基于 CWD」的基准漂移。

- 空串 `export_dir` 防御：`_safe_output_path` 返回 None 时回退原始值，保持旧行为（`Path("")` → CWD）。
- M-1 / M-10 / M-12 / N-2 的输入均为内部生成路径（tmp/bak/导出目标），无新增外部参数面。

### T1（M-1）atomic_write：chmod 防护 + finally 可写清理 + 只读目标用例

- **改动文件**：`flashgaze/utils/atomic_write.py`、`tests/test_atomic_write.py`
- **输入/输出**：输入=既有 `_atomic_write` 写入路径；输出=chmod 失败不再中断落盘；任何退出路径（含 replace 抛错）后无 `.tmp` 残留、且清理本身不抛异常。
- **具体改法**：
  1. 98-102 两处 `os.chmod` 包 `try/except OSError: pass`（与 105-110 chown 的防护对称），注释说明权衡：chmod 失败时 tmp 按默认 umask 权限落盘（权限继承为 best-effort），不阻断写入。
  2. `finally`（113-115）改为：先 `try: os.chmod(tmp, 0o666) except OSError: pass`（成功路径 tmp 已随 replace 消失，chmod 抛 FileNotFoundError 被吞），再 `tmp.unlink(missing_ok=True)`——避免 tmp 为只读（如 0o444）时 Windows unlink 抛 PermissionError 掩盖 replace 的原始异常。
- **基础测试用例**（tests/test_atomic_write.py 新增）：
  - `test_readonly_target_rejected_leaves_no_tmp`（skipif 非 Windows）：目标 0o444 → `atomic_write_bytes` 抛 PermissionError、目录无 `.tmp.*` 残留、原文件字节不变；
  - `test_readonly_target_posix_replaced_in_place`（skipif 非 POSIX）：replace 成功且 mode 保持 0o444；
  - `test_chmod_failure_still_writes`：monkeypatch `os.chmod` 抛 OSError → 写入成功、内容正确（无残留）。
- **验收标准**：`python -m pytest tests/test_atomic_write.py -q` 全部通过。
